# Incline Implementation Plan

**Goal:** Build the approved visual taste quiz with plural, contextual, editable preferences.

**Architecture:** A client interface uses a pure preference module and curated specimen definitions. Device-local sessions store raw answers and explicit user edits separately. No inference crosses project boundaries.

**Tech Stack:** React, TypeScript, Vinext, installed Shadcn primitives, Node test runner.

**Spec:** ../../design.md

## Global constraints
- Multiple preferences must coexist.
- Relative preference is not absolute approval or rejection.
- Context and exploration belong to each project.
- Storage is local to this browser; export is explicit.

## Tasks
1. Write failing behavioral tests in `lib/taste.test.ts` against `deriveProfile`, `getRounds`, `reviseAnswer`, `parseSaved`, and `exportMarkdown`. Establish module types and minimal stubs in `lib/taste.ts`; run `node --test lib/taste.test.ts` and confirm assertion failures.
2. Implement the evidence model and curated adaptive rounds. Keep unanswered dimensions unknown, reject malformed saved data, and preserve all sessions on revision. Pass the tests.
3. Build `app/page.tsx`, `components/incline/specimen.tsx`, and `app/globals.css` around setup, comparison, and profile states. Use installed radio, progress, button and checkbox primitives. Keep profile editing distinct from inferred evidence. Add storage failure messaging and export actions.
4. Validate with Node tests, TypeScript, lint, production build, and HTTP response. Preview after the coherent core is ready. Save and privately publish the validated version using Sites.

Execution is inline; the user has authorized proceeding with the discussed design.
